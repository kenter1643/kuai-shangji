# 快商机 · 全国招投标商机系统

覆盖全国 34 个省级行政区的招投标商机发现系统。自带真实采集器，从国家法定发布平台
抓取公开招标信息，做结构化、去重、阶段判定与商机匹配，最终以移动端 H5 呈现。

---

## 数据源选型（实测结论）

招投标数据天生分散在各级平台，且普遍有频控和 CORS 限制。项目对 12 个候选源做了
实际抓取测试，最终选型如下：

| 数据源 | 实测结论 |
|---|---|
| **中国政府采购网** `search.ccgp.gov.cn/bxsearch` | ✅ **全国主源**。支持 `displayZone` + `zoneId` 按省级行政区分片检索，一份解析器覆盖全国 32 个省级区 |
| **广东省政府采购智慧云平台** `gdgpo.czt.gd.gov.cn` | ✅ **广东主源（REST 接口）**。覆盖省本级 + 20 个地市共 237 个区县切片，列表接口直接带预算金额 |
| 全国公共资源交易平台 `ggzy.gov.cn` | ❌ 连接超时，不可用 |
| 省级站「新点」搜索接口 `inteligentsearch/getFullTextData` | ❌ 站点已换版，全部 404 |
| 中国招标投标公共服务平台 `cebpubservice.com` | ⚠️ 可访问，但公开页只有通知类内容，非数据列表 |
| 广州公共资源交易中心 `ywtb.gzggzy.cn`（工程类） | ⚠️ 站点可访问，但列表由 JS 渲染、静态 HTML 无条目，需另找接口 |
| 采购意向 / 需求公示 | ❌ 国家级平台未开放检索入口；省平台有栏目但接口查得 0 条（见「已知限制」） |

### CCGP 的两条硬性约束（踩过的坑）

1. **裸请求首次必返「频繁访问」拦截页** —— 必须先访问一次 `www.ccgp.gov.cn`
   建立会话 cookie，后续请求才正常。采集器在 `HttpClient.warmup()` 中处理。
2. **请求间隔不得低于 1 秒** —— 否则触发 IP 级限流。偶发返回 0 条通常是超时，
   并非地区编码错误，重跑即可。

### 广东源：`pageNo` 翻页是失效的（最重要的一个坑）

实测证明服务端**完全忽略 `pageNo`**：`pageNo=1/2/3/5/10` 返回的是一模一样的
最新 40 条（按 `noticeTime` 倒序，精度到分钟），去重后只有 41 条。
**靠翻页拿历史数据这条路是死的。**

能真正切分数据的维度是这三个，且可以互相叠加（每个切片最多回 40 条）：

| 切片维度 | 说明 |
|---|---|
| `regionCode` | 区县代码，全省 237 个切片（省本级 + 22 市 + 215 区县） |
| `title` | 标题关键词，服务端模糊检索，如「智能化」命中 4381 条 |
| `noticeType` | 公告类型编码 |

所以广东源的采集策略是**横向切片而非纵向翻页** —— 遍历「区县 × 关键词」矩阵，
每个组合取最新 40 条。由此带来的一个语义差异：**`--pages N` 在广东源里是
「每个区县跑几个关键词切片」，不是翻页数。**

> 深圳市（4403）不在省平台区划表内，接口查深圳各区也全部返回 0 条 ——
> 深圳用自己独立的采购平台，不在省云上。要覆盖深圳需另接深圳源。

## 快速开始

```bash
git clone https://github.com/kenter1643/kuai-shangji.git
cd kuai-shangji
pip3 install -r requirements.txt

# 采集全国数据（首次约 6-8 分钟）
python3 -m collector.run

# 本地预览
python3 -m http.server 8777
# 浏览器打开 http://127.0.0.1:8777/index.html
```

采集结果写入 `data/tenders.db`（SQLite），并导出 `data/tenders.json` 供前端读取。

## 数据存储（统一入库）

`data/tenders.db` 是**唯一权威数据源**，前端 JSON 只是导出快照。三张表各司其职：

| 表 | 主键 | 内容 | 为什么要分开 |
|---|---|---|---|
| `tenders` | `id`（URL md5） | 列表字段 + 金额 / 中标人 / 截止 / 行业分类 | 列表查询与筛选的主力，必须轻 |
| `tender_content` | `id` | 正文 + 结构化 JSON | 正文单条数 KB ~ 数十 KB，混进主表会拖慢查询与导出 |
| `contacts` | 自增 | 联系人（角色 / 单位 / 姓名 / 手机 / 座机 / 邮箱 / 关联公告） | 一条公告有多位联系人，竖表才能按人检索与复用 |

跨源去重仍以 URL md5 为主键；老库缺列时启动时自动 `ALTER`（含分类、正文标记）。

导出两个 JSON 供 H5 读取：

- `data/tenders.json` —— 列表（首屏加载，3.7MB）
- `data/details.json` —— 正文 + 结构化 + 联系人（点开详情 / 通讯录时才拉，按需加载）

### 常用命令

```bash
python3 -m collector.run                          # 全国全量（CCGP）
python3 -m collector.run --regions 北京市,广东省    # 只采指定地区
python3 -m collector.run --pages 3                 # 加大翻页深度（CCGP）
python3 -m collector.run --skip-list --detail 300  # 跳过列表，只补详情
python3 -m collector.run --reset-stage 中标结果     # 重置某阶段详情标记以便重抓
python3 -m collector.run --delay 2.0               # 放慢节奏（被限流时用）

# 广东源：按 237 个区县切片采集，--pages 是「每个区县的关键词切片数」
python3 -m collector.run --source gdgpo --pages 2 --detail 200
python3 -m collector.run --source gdgpo --kw 智能化,安防   # 只跑指定关键词切片
python3 tools/fetch_gd_regions.py                  # 刷新广东区县切片表

# 正文补录：把「已抓详情但正文未入库」的记录重抓正文（跨源自动识别）
python3 -m collector.run --rebuild-content 500

# 行业分类补录（不联网）
python3 -m collector.run --backfill-category --recat
```

两个源的 `--pages` 含义不同，别混用：CCGP 是翻页数，广东源是关键词切片数。

## 系统架构

```

├── base.py               HTTP 客户端（限速/重试/会话预热）+ 招投标字段抽取
├── sources/
│   ├── ccgp.py           中国政府采购网适配器（HTML 解析）
│   ├── gdgpo.py          广东省政府采购智慧云平台适配器（REST 接口 + 区县切片）
│   └── gd_regions.json   广东 237 个区县切片表（由 tools/fetch_gd_regions.py 生成）
├── store.py              SQLite 存储、去重、详情增量、导出 JSON
├── classify.py           行业分类词典与打分（20 个行业，支持多标签）
├── extract.py            正文清洗、结构化字段、联系人抽取
└── run.py                采集入口（列表 → 详情 → 正文入库）

tools/
└── fetch_gd_regions.py   从平台区划接口拉取并固化广东区县切片表

web/                      前端（移动端优先单页）
├── style.css
├── app.js                渲染、筛选、统计、详情抽屉、通讯录、预警、对手分析、匹配
index.html                入口页面
data/                     采集产物（tenders.db 权威源 + tenders.json / details.json 快照）
```

### 两阶段采集

| 阶段 | 成本 | 产出字段 |
|---|---|---|
| **列表** | 低，每页 20 条 | 标题、链接、发布时间、采购人、代理机构、公告类型、地区、品目 |
| **详情** | 高，1 条 1 次请求 | 预算金额、中标人、投标截止时间、联系人、电话 |

详情阶段按 `--detail` 配额控制，**且优先分配给「中标结果」类公告** —— 中标人字段
只存在于这类正文；配额若平均分给招标公告，对手分析会拿不到样本。

### 公告阶段判定

按标题关键词归类，这是商机分层的基础：
`招标公告` · `中标结果` · `前置预警` · `变更公告` · `异常公告` · `其他`

### 正文清洗与结构化

`collector/extract.py` 把详情页 HTML 洗成三类可复用资产：

| 产出 | 落库位置 | 说明 |
|---|---|---|
| 正文 `content` | `tender_content` 表 | 剔 script/style → 块级标签转行 → 去页眉页脚噪声行 → 剔除平台页脚客服电话 |
| 结构化 `structured` | `tender_content` 表 | 项目编号 / 采购方式 / 预算 / 中标价 / 中标单位 / 投标截止 / 开标时间 / 采购人 / 代理机构 |
| 联系人 `contacts` | `contacts` 表 | 按角色分条：采购人 · 代理机构 · 项目联系人，含单位、姓名、手机、座机、邮箱 |

两个踩过的坑：

1. **平台页脚电话会混进正文**（CCGP 全国统一 `010-63819289`），不剔除会被当成项目联系人；
2. **采购方式不能全文匹配** —— 正文常有「评审专家（**单一来源**采购人员）名单」，
   会把公开招标误判成单一来源。优先级：正文「采购方式：」键 → 标题 → 正文开头 600 字。

### 行业分类识别

`collector/classify.py` 用一套**带权重的行业关键词词典**给每条公告打行业标签：

```
score[类目] = Σ(标题命中权重) × 3 + Σ(采购人命中权重) × 1
```

- 得分最高者为主分类 `category`；得分 ≥ 主分类 45% 的其它类目一并写入
  `categories`，形成**多标签** —— 「学校智能化改造」同时属于
  「智能化与信息化」和「教育装备」，多选筛选两边都能命中（最多 3 个标签）。
- 主分类得分过低时宁可判 `其他`，避免弱词误导筛选。当前 12923 条数据
  分类覆盖率 **96%**，其中 37% 带多个标签。
- 纯规则、可解释、零依赖：新增赛道只需往 `CATEGORY_RULES` 里加词。

20 个行业：智能化与信息化 / 安防与消防 / 办公设备与耗材 / 办公家具 /
建筑工程与装修 / 物业服务 / 印刷与广告 / 车辆与交通 / 机电空调电梯 /
医疗卫生 / 教育装备 / 法律咨询服务 / 食品与餐饮 / 环保环卫绿化 /
能源与节能 / 科研仪器设备 / 服装与劳保 / 文体与旅游 / 农林水利 / 其他。

分类在**入库时自动完成**（列表阶段即可定类，不依赖详情抓取）。历史数据补录：

```bash
python3 -m collector.run --backfill-category           # 只补空分类（增量）
python3 -m collector.run --backfill-category --recat   # 词典大改后全量重算
```

## H5 功能

**商机广场** —— 按地区 / 阶段 / 金额区间 / 时间 / 数据源 / 关键词多维筛选，关键词命中处高亮。

**行业分类多选** —— 20 个行业标签可任意勾选，命中任一即保留（并集筛选）；
标签带命中条数，默认收起两行、可展开全部，一键清空。卡片上直接显示所属赛道。

**机会预警** —— 三类已在数据中确证的商机信号：
- 废标 / 终止：项目会重新招标，可提前备标
- 更正 / 澄清：需求或资质门槛正在松动
- 14 天内截止：当下还能抢的窗口

**公告详情** —— 点卡片标题打开全屏详情页：结构化信息（项目编号 / 采购方式 /
预算 / 中标价 / 截止 / 开标 / 采购人 / 代理机构）+ 联系人卡片（一键拨号）+
清洗后的公告正文（长正文折叠，一键展开）。正文按需加载，不进首屏。

**通讯录** —— 从所有已采集正文里解析出的联系人库，按角色（采购人 / 代理机构 /
项目联系人）筛选、按姓名 / 单位 / 电话 / 项目搜索，点击直接拨号，可回跳所属公告。

**对手分析** —— 行业分布（哪些赛道项目最多）、中标单位榜（谁在拿单）、
代理机构榜（谁在操盘）、采购人榜（谁在持续买单）、地区分布（资源投放参考）。

**AI 匹配** —— 填写企业能力画像（关键词 / 目标省份 / 承接金额区间），
系统按五维加权给每条商机打分并按匹配度排序。评分规则在页面内可解释：
能力词命中 50 分、地域 15 分、金额适配 15 分、阶段价值 12 分、时效窗口 8 分。

## 已知限制

1. **采购意向（立项前置信息）尚未接入。** 国家级平台没有开放采购意向检索，
   真正的立项前置数据分布在各省财政厅，需逐个对接。当前「机会预警」改用
   数据中确实存在的三类信号实现。
2. **当前以政府采购口径为主。** 企业 / 央企类（国家电网、三桶油、三大运营商、
   铁路、军队采购网）各自独立且反爬策略差异大，尚未接入。
3. **AI 匹配是本地加权算法，未调用大模型。** 好处是实时、可解释、零成本；
   如需语义级匹配可再接入 LLM。
4. **详情覆盖率受配额限制。** 金额、中标人等字段只存在于正文，
   提高 `--detail` 配额可提升覆盖率。

## 扩展采集器

新增数据源只需两步：

1. 在 `collector/sources/` 下新建适配器，继承 `BaseSource`，
   实现 `regions()` 与 `fetch(region)`，返回字段与现有结构一致的 `dict` 列表；
2. 在 `collector/run.py` 的 `SOURCES` 字典中注册。

存储层以 `url` 的 md5 摘要做主键，跨源重复会自动合并。
